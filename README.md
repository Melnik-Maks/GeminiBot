# GeminiBot

Telegram-бот для продажу Google AI Pro (Gemini Pro) на 18 місяців за 200 грн.
Оплата — переказ на картку, квитанція — фото або PDF, підтвердження оплати й видача подарункового посилання — вручну адміністратором.

## Що реалізовано

- Українське меню з описом, інструкцією, покупкою, історією замовлень і прямим переходом у чат адміністратора.
- Навігація в одному повідомленні: текст і кнопки оновлюються на місці; «Назад» повертає до замовлення, списку або меню.
- Команди /start і /menu надсилають меню новим повідомленням унизу чату та прибирають попереднє меню після успішного надсилання.
- Головне меню містить фото assets/a1.png, опис і кнопки в підписі. «Як активувати» показує альбом assets/12pro1.png–12pro4.png у цьому порядку та текст інструкції з кнопкою «Назад» під ним. При переході на інший екран зображення інструкції прибираються; стан навігації зберігається після перезапуску.
- Перед показом реквізитів покупець переглядає ціну та час видачі — 1–5 хв.
- Квитанції до 10 МБ; повторне надсилання після відхилення зберігається в тому самому замовленні.
- Адміністратор отримує квитанцію, звіряє зарахування в банку та підтверджує оплату кнопкою «Перевірив зарахування».
- Лише після підтвердження оплати можна підготувати посилання, переглянути покупця й підтвердити відправлення.
- Перевірка повторного використання файлу квитанції й того самого посилання; захист від повторного підтвердження оплати замовлення.
- Покупець бачить тільки власні замовлення; адмін-доступ перевіряється за числовим ID.
- Кнопки «Написати адміну» та «Потрібна допомога» відразу відкривають особистий чат адміністратора.
- Адміністратор також може надіслати повідомлення покупцю через картку замовлення; історія попередніх звернень збережена.
- Пошук замовлення, черги перевірки та видачі, статистика, рекламні джерела.
- Сповіщення всім адміністраторам про нового користувача: ім’я, username, Telegram ID, джерело переходу та кнопка відкриття профілю.
- Ціна, час видачі й призупинення продажів змінюються через адмін-меню.
- Фіксація фактичного повернення через банк з окремим підтвердженням.
- SQLite, журнал дій, збережені сесії введення, черга повторної доставки.
- Резервне копіювання та шаблони systemd для сервера.

## Запуск на Windows

Потрібен Python 3.12+. У цій робочій папці середовище .venv та залежності вже встановлені.

Для нового комп'ютера виконайте з папки проєкту:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
Copy-Item .env.example .env
~~~

Заповніть .env локально, не публікуючи токен:

| Поле | Значення |
| --- | --- |
| BOT_TOKEN | Токен бота, створеного через @BotFather |
| ADMIN_IDS | Ваш числовий Telegram ID; кілька ID — через кому |
| ADMIN_USERNAME | Публічний Telegram username адміністратора для кнопки прямого переходу |
| PAYMENT_CARD | Номер картки з 16 цифр |
| PAYMENT_RECIPIENT | Ім'я отримувача, яке побачить покупець |
| PAYMENT_BANK | Назва банку, необов'язково |
| PRICE_UAH | 200 за замовчуванням |
| DELIVERY_TIME | 1–5 хв |
| DATABASE_PATH | data/bot.sqlite3 |
| GIFT_ALLOWED_HOSTS | Необов'язковий список точних дозволених доменів через кому |
| SALES_OPEN | false для початкового налаштування |

Перевірка налаштувань без запитів у Telegram:

~~~powershell
.\.venv\Scripts\python.exe -m gemini_bot --check
~~~

Запуск:

~~~powershell
.\.venv\Scripts\python.exe -m gemini_bot
~~~

Або запустіть run.ps1 із PowerShell.

Кожен адміністратор має відкрити чат із ботом і натиснути /start, інакше Telegram не дозволить боту надсилати йому повідомлення.
Команда /id показує числовий ID того, хто її викликав. Доступ не визначається за @username.

Відкрийте /admin → «Налаштування», перевірте ціну й час видачі та увімкніть продажі.
Бот працює, доки запущений процес. Для цілодобової роботи використовуйте сервер.

PRICE_UAH, DELIVERY_TIME та SALES_OPEN з .env застосовуються при першому створенні бази.
Надалі ці три параметри зберігаються в SQLite та змінюються через адмін-меню.
Зміна ціни не змінює суму вже створених замовлень.
Під час оновлення старий початковий текст часу видачі одноразово замінюється на 1–5 хв у налаштуваннях, активних замовленнях і недоставлених повідомленнях.

## Робота адміністратора

Кнопки меню оновлюють поточне повідомлення. Якщо Telegram не дозволяє редагування або це фото/PDF,
бот спочатку створює новий екран, а потім прибирає попередній. Якщо старе повідомлення вже не можна видалити,
бот за можливості прибирає з нього кнопки.
«Назад» у формі введення скасовує лише введення; підтверджена оплата або саме замовлення не скасовуються.
Повернення з картки замовлення зберігає останню сторінку й фільтр списку.
Тимчасові копії квитанцій та історії звернень прибираються з чату при виході з перегляду; записи у базі залишаються.
Нові оплати, нові користувачі та видача посилання й далі надходять окремими сповіщеннями.
Кнопка зв'язку з адміністратором відкриває особистий чат напряму.

1. Покупець надсилає квитанцію — бот показує її в адмін-чаті.
2. Звірте суму, отримувача, дату та зарахування у своєму банку.
3. Натисніть «Перевірив зарахування». Оплата одразу підтверджується, а бот просить посилання для активації.
4. Вставте HTTPS-посилання. Номер банківської операції вводити не потрібно.
5. Перевірте номер замовлення, покупця й посилання та натисніть «Надіслати покупцю».
6. Після успішної відповіді Telegram бот повідомить про доставку.

«Назад» повертає до оплаченого замовлення. Продовжити введення можна кнопкою «Видати посилання».
Для окремого перегляду вкладень є кнопка «Квитанції». Бот не перевіряє зарахування автоматично.

Для відхилення квитанції вкажіть причину: покупець отримає її та зможе надіслати квитанцію повторно.

«Зафіксувати повернення» **не переказує кошти**. Спочатку виконайте повернення в банку, потім введіть номер операції й підтвердьте результат у боті.
Повернення доступне для підтвердженої оплати або вже виданого замовлення.

«Активував» — добровільне підтвердження покупця. Бот не має доступу до Google-акаунта та не перевіряє активацію в Google.

## Підтримка

Кнопки «Написати адміну» та «Потрібна допомога» містять пряме посилання на чат адміністратора.
Натискання одразу відкриває чат; бот не просить вводити запитання й не пересилає його.
ADMIN_USERNAME задає адресу цього чату, наприклад username без @. Це контакт для підтримки, а не право доступу до адмін-меню: доступ визначається тільки ADMIN_IDS.
Якщо ADMIN_USERNAME порожній, використовується Telegram-посилання за першим ID з ADMIN_IDS; його доступність залежить від налаштувань приватності адміністратора. Для надійного переходу вкажіть публічний username.

Команди /support та /paysupport показують кнопку прямого переходу. Старі callback-кнопки також показують нове посилання.
Для нових кнопок у вже відкритому боті натисніть /start після оновлення процесу.

Листування в особистому чаті бот не читає й не зберігає. Попередня історія звернень і можливість надіслати покупцю повідомлення з адмін-меню залишаються доступними.
Сесії введення квитанцій і дій адміністратора зберігаються протягом години; /cancel скасовує тільки введення, а не замовлення.

## Реклама

При першому запуску бота новим користувачем адміністратор отримує сповіщення.
Повторні /start, зміна імені та перезапуск бота не створюють повторних сповіщень.
Про вже наявних у базі користувачів і самих адміністраторів сповіщення не надсилаються.
Сповіщення зберігається разом із реєстрацією користувача та доставляється через загальну чергу з повторними спробами.

Використовуйте окремі стартові посилання:

~~~text
https://t.me/YOUR_BOT_USERNAME?start=instagram_campaign1
https://t.me/YOUR_BOT_USERNAME?start=tiktok_video2
~~~

Зберігається джерело першого запуску користувачем. Дозволені латинські літери, цифри, підкреслення і дефіс, до 64 символів.
Статистика показує користувачів і кількість підтверджених оплат за джерелами. Це не облік показів або всіх кліків по рекламі.

## Доставка й надійність

Статуси: awaiting_payment → review → paid → delivery_pending → issued → activated.
Додаткові: rejected, cancelled, refunded.

Зміна бізнес-статусу та постановка пов'язаних сповіщень у чергу записуються однією транзакцією.
Бот позначає посилання виданим після успішної відповіді Telegram.
Тимчасові помилки повторюються з паузами; після 10 невдалих спроб повідомлення очікує ручного повтору.
Постійні помилки Telegram (наприклад, блокування бота) зупиняють автоматичні спроби одразу.

Адміністратор бачить недоставлені повідомлення в меню та може повторити доставку.
Покупець може розблокувати бот і натиснути /start: його зупинені повідомлення повернуться до черги.
Якщо Telegram недоступний для всіх, сповіщення адміну також чекатиме відновлення зв'язку.

Видача одного замовлення не створює друге посилання. Проте Telegram не надає ключа ідемпотентності для sendMessage:
якщо процес аварійно завершиться між прийняттям повідомлення Telegram та записом результату в SQLite,
можливе повторне повідомлення з **тим самим** посиланням.

Запускайте один екземпляр на одну базу й один токен.
Файлове блокування запобігає другому процесу з тією самою базою на одному сервері.
Ця версія не призначена для кількох серверів із загальною мережевою SQLite-базою.

## Дані та резервні копії

Квитанції й вкладення зберігаються як Telegram file_id, без завантаження на диск.
Перевірка типу файла спирається на метадані Telegram; бот не виконує вкладення й не розпізнає платіж автоматично.
Файловий відбиток виявляє повтор того самого файла, але не змінену фотографію тієї самої квитанції — тому перевірка банку обов'язкова.

База містить Telegram ID, імена, замовлення, тексти звернень, номери операцій і подарункові посилання.
Вона не зашифрована на рівні застосунку. Обмежте доступ до .env, data та резервних копій.
Токен, квитанції й повні посилання не виводяться в штатні журнали застосунку.

Узгоджена резервна копія працюючої SQLite-бази:

~~~powershell
.\.venv\Scripts\python.exe -m gemini_bot.backup --database data/bot.sqlite3
~~~

Результат з'явиться в backups із часом UTC у назві.
Якщо змінено DATABASE_PATH, передайте цей самий шлях у --database.
Команда використовує SQLite Backup API та перевіряє цілісність копії.

Для відновлення зупиніть бот, збережіть поточні bot.sqlite3, bot.sqlite3-wal і bot.sqlite3-shm в окреме місце,
потім покладіть резервну копію на місце основного файла.
Не залишайте старі -wal/-shm поруч із відновленою базою.
Після відновлення перевірте останні платежі: дії після моменту копії можуть бути відсутні.

## Сервер Linux

Шаблони у deploy/ розраховані на:
- окремого користувача geminibot;
- проєкт /opt/gemini-bot;
- середовище /opt/gemini-bot/.venv;
- доступ користувача geminibot до data та backups.

Створіть Python-середовище на сервері та встановіть requirements.lock.txt; Windows-папку .venv переносити не потрібно.
Заповніть .env, створіть data й backups, перевірте --check.
Після встановлення service-файлів у /etc/systemd/system:

~~~bash
sudo systemctl daemon-reload
sudo systemctl enable --now gemini-bot.service
sudo systemctl enable --now gemini-bot-backup.timer
sudo journalctl -u gemini-bot.service -f
~~~

Таймер створює щоденні локальні резервні копії. Видалення старих копій і копіювання на інший носій налаштовуються окремо.

## Перевірка

~~~powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
~~~

Тести використовують тимчасову або оперативну SQLite-базу та тестову Telegram-сесію;
не надсилають реальних повідомлень, не перевіряють реальні перекази та не активують подарункові посилання.

Перевіряються покупка, фото/PDF, повторні події, підтвердження оплати, захист від чужого доступу,
унікальність платежів і посилань, застарілі підтвердження, підтримка, повернення, перезапуск, backup та помилки доставки.

Перед рекламою проведіть контрольний сценарій з окремим Telegram-акаунтом покупця:
покупка → квитанція → перевірка в банку → видача → підтримка.

## Умови платформи та товару

Реалізований погоджений сценарій переказу на картку.
Telegram вимагає Stars для цифрових товарів усередині ботів; цей спосіб оплати не відповідає цій вимозі:
[документація Telegram](https://core.telegram.org/bots/payments-stars).

Тривалість 18 місяців наведена за описом продавця.
Перевірте її, дозволені акаунти/регіони, строк дії посилання й умови повернення для вашої конкретної пропозиції перед запуском продажів.
Бот перевіряє синтаксис та унікальність посилання, а не його чинність у Google.
Він не відкриває подарункові посилання автоматично.
Поради щодо Google Диска та банківських карток не включені до умов без підтвердження.

Технічна основа: [aiogram](https://docs.aiogram.dev/en/latest/), [Telegram Bot API](https://core.telegram.org/bots/api).
